# 全自动运行契约 · autopilot contract

> 这份文件定义**agent 在无人值守时该怎么跑**。读它的顺序在 SKILL.md 之后、
> pipeline_steps.md 之前。

---

## 一、唯一的输入

```
python scripts/autopilot.py start --dir <项目文件夹> --direction "<方向或题目>"
```

**用户只给这一句话。** 其余全部由流水线自己推断并记录在 `DECISIONS.md`：

| 需要定的东西 | 怎么定 |
|---|---|
| 论文类型 | 方向里出现 review/survey/综述 → 综述；否则研究论文 |
| 目标期刊 | 按方向关键词匹配内置的刊表（含分区、是否免费、篇幅量级） |
| 分区 / APC | 同上；表中已标注"订阅制刊通常免费、全 OA 的 Q4 常收费" |
| 篇幅 / 图表 / 参考文献上限 | 取该刊常见量级 |
| 是否有实验数据 | 用户没说 → 按 `simulation-only` 处理，并在摘要和范围声明里写明 |
| 作者与单位 | **一律占位符**——不臆造真实人物信息 |

**用户想改哪一条，直接改 `DECISIONS.md`；流水线下一轮会读到。**

---

## 二、主循环（每一步就三个命令）

```
1. python scripts/autopilot.py next  --dir <folder>      # 拿工单
2. 按工单做事，产出写到工单指定的路径
3. python scripts/autopilot.py done  --dir <folder>      # 交工
```

`next` 会打印：目标刊与篇幅、**必须产出的文件路径**、通过标准、该读哪份参考文件。
`done` 会**核对产出是否真的存在且非空**——缺文件或只有几十字节，会被拒绝前进。

这个拒绝机制是整套东西里最重要的部分：**它让"跳过某步"变得不可能悄悄发生。**

---

## 三、绝不停下来提问

**全自动模式的定义就是：不向用户提问。**

原来属于"问题"的东西，现在各自有归宿：

| 本来会问 | 现在怎么办 |
|---|---|
| 投哪个刊？ | 按方向匹配刊表，记录到 `DECISIONS.md` |
| 篇幅多少？ | 取该刊常见量级，记录 |
| 有没有实验数据？ | 按最保守假设（无）处理并写明，记录 |
| 作者是谁？ | 占位符，第 20 步会提醒替换 |
| 某个选择拿不准？ | **选一个能自圆其说的，记录下来，继续走** |
| 检索不到结果？ | 换公开 API（OpenAlex / Crossref），再不行降级并记录 |
| 某步做不了？ | `skip --reason "..."` 降级，继续走 |

**唯一允许停下来的情况**（这几种停下来是负责，不是偷懒）：

1. **完全没有联网能力**，且该步必须联网（检索、选刊核查）
2. **方向本身自相矛盾或空到无法推断**（例如只给了两个字）
3. **发现已经发表过完全相同的论文**——这时必须让用户决定

停下来时要**明确说清是哪一条**、已经完成了哪些步、当前状态文件在哪。

## 四、降级必须留痕

做不了的步骤用：

```
python scripts/autopilot.py skip --dir <folder> --step <NN> --reason "<为什么>"
```

会产生：

- 状态文件里记 `degraded: true` + 原因
- `PIPELINE.md` 里该步显示为「降级完成」
- `DECISIONS.md` / 日志里留痕
- **`selfcheck.py` 会检查这些降级有没有写进最终交付说明——没写就是阻断项**

**降级可以，瞒着不行。** 这条不是道德说教，是实用考虑：
审稿人迟早会发现缺的那块，与其被问，不如自己在局限里先讲清楚。

## 五、每步干完的自检

```
python scripts/selfcheck.py --dir <folder>
```

它查的是**内容层面**的东西，不只是文件在不在：

| 查什么 | 为什么 |
|---|---|
| 残留占位符（TODO / 待补 / 占位 / XXX） | 交出去会被审稿人一眼看到 |
| **正文数字 vs `data/` 里的数字** | 找不到来源的数字，要么是笔误要么是编的 |
| 正文引用但没画出来的图 | 图号错位是常见退稿理由 |
| 图号不连续 | 同上 |
| 引用了但文献表里没有的编号 | **审稿人对引用造假零容忍** |
| 文献表里列了但正文没引用的 | 多数刊要求删 |
| 降级步骤有没有写进交付说明 | 见第四节 |
| 去 AI 痕迹判定项 | 见 `deai_protocol.md` |

**注意它的定位**：这是**可自动核对的部分**，它通过 ≠ 论文正确。
数字算得对不对、引用内容与原文是否一致，仍然要人（或另一个模型）核。

### 数字溯源要求 `data/` 里必须有"派生量"

`selfcheck.py` 是这样核对数字的：把正文里的数字和 `data/` 里出现的数字比对，
正文有而 data 没有的会被标出来复核。所以**光存求解器的原始输出是不够的**——
正文里大量数字是**派生量**，必须一起存进 `data/`：

| 正文里会写的 | 该存到 data/ 的 |
|---|---|
| "降低了 86.4 %" | 派生量表中一行：`peak_reduction, 86.4, percent` |
| "网格从 12 万加密到 190 万单元" | 参数表中三行网格规模 |
| "比被动方案好 30.8 %" | 派生量表中一行 |
| 几何尺寸、材料参数 | 参数表（带单位与来源列） |

**做法**：第 12 步写完方法与结果后，导出一张 `data/derived_kpi.csv`
和一张 `data/tab_parameters.csv`，把正文出现的每一个数字都放进去。
这样自检能一次过，而且**别人复算你的论文时也只需要看这两张表**。

这一条是本轮自测时发现的：第一版自检把正文里 50 % 的数字都标成了"来源不明"，
原因不是数字错，而是 data/ 里只有原始输出、没有派生量。

## 六、什么算跑完

先跑一次自检确认这套装置在你机器上是好的：

```
python scripts/selftest.py
```

它会建一个临时项目、无人值守走完 21 步、验证拒绝机制真的会拒绝、
再跑 `selfcheck.py`，最后打印 `PASS`。**换一台电脑或换一个 AI 之后先跑这个。**

`autopilot.py check` 显示 22 步全部完成、`selfcheck.py` 没有阻断项，
才叫跑完。此时项目文件夹里应当有：

```
<项目文件夹>/
├── PAPER_STATE.json          # 机器可读进度
├── PIPELINE.md               # 人可读进度
├── DECISIONS.md              # 所有自动决策（用户事后可改）
├── SELFCHECK.md              # 最后一次自检报告
├── 00_…/ … 21_…/             # 22 个步骤的产出
├── refs/                     # 文献库与导出
├── data/                     # 数据与原始输出
├── figures/                  # 图件
├── manuscript/               # 正文分节 Markdown + 参考文献
├── journal_papers/           # 目标刊同体裁文章（建文风基线用）
└── submission/               # 投稿包
```

外加一份**交付说明**，内容必须包含：

1. 做完了什么、每步产出的位置
2. **所有降级项及其原因**（`selfcheck.py` 会强制）
3. **所有未核实项**（查不到的引用、拿不到的政策页……）
4. 用户投稿前必须自己做的事（补真实作者信息、填 DOI、查当日期刊政策）

## 七、给 agent 的执行纪律

1. **不要为了"看起来完整"而编造。** 缺就写缺。`selfcheck.py` 拦不住编造，
   但审稿人能。
2. **不要跳过第 19 步。** 它是投稿前唯一的文体终检，且必须在第 20 步之前。
3. **不要用"通过检测器"当验收标准**（见 `deai_protocol.md` 第四节）。
4. **每步产出落到工单指定的路径**，不要自创目录结构——
   否则 `done` 会拒绝，`selfcheck` 会漏检。
5. **决策和降级都要写下来。** 一个没有 `DECISIONS.md` 的全自动运行，
   等于用户事后无从复核。
6. **遇到本轮学到的新坑，补进对应的 `references/*.md`。**
   这个技能是靠踩坑长起来的，不写下来下次还会踩。
