# 中文学位论文格式规范（thesis-pipeline 参考）

> **重要前提**：本文给出的是**通用规范**（GB/T 7713.1 学位论文编写规则、GB/T 7714 参考文献著录规则）。
> **你所在学校的具体模板优先**。拿到模板后，逐项比对并把差异写进 `thesis.json`——
> 排版的唯一真源是 `thesis.json`，不要改脚本。

---

## 一、页面与字体（默认值，按 thesis.json 可改）

| 项目 | 默认值 | 常见学校要求 | 备注 |
|---|---|---|---|
| 纸张 | A4（21 × 29.7 cm） | A4 | |
| 页边距 | 上下 2.54 cm、左右 2.8 cm | 上 2.5–3.0、下 2.5、左 3.0（装订侧） | 左侧常需多留 0.5 cm |
| 正文 | 宋体 小四（12 pt），行距 22 pt | 宋体/仿宋 小四，1.5 倍行距 | 22 pt ≈ 1.5 倍 |
| 章标题 | 黑体 三号（16 pt）居中 | 黑体 三号 | |
| 节标题 | 黑体 四号（14 pt）左对齐 | 黑体 四号 | |
| 三级标题 | 黑体 小四（12 pt） | 黑体 小四 | |
| 首行缩进 | 2 字符 | 2 字符 | 必须用 `w:firstLineChars`，用固定磅值会错位 |
| 图表题注 | 宋体 五号（10.5 pt）居中 | 宋体 五号 | 图题在下、表题在上 |
| 参考文献 | 宋体 五号，悬挂缩进 | 同 | |
| 页码 | 页脚居中，阿拉伯数字 | 正文起编，目录用罗马数字 | 本工具暂只做统一阿拉伯数字 |

**常见坑**：`python-docx` 的 `add_heading()` 会把中文渲染成 MS-Gothic（日文字体），
因为内置 Heading 样式没有 `eastAsia` 字体。本工具的 `build_docx.py` 不用内置标题样式，
而是自建段落并显式设置 `w:eastAsia`，避免该问题。

## 二、章节结构（按类型）

| 类型 | 建议章节 |
|---|---|
| 本科 | 绪论 / 理论基础 / 研究设计 / 结果与分析 / 结论与展望（5 章） |
| 硕士 | 加"文献综述"独立成章（6 章） |
| 博士 | 加"创新点总结"或按研究内容分 3–4 个成果章（7 章） |

必备部件（`final_check.py` 检查）：
封面 → 摘要（中文）→ Abstract（英文）→ 目录 → 正文各章 → 参考文献 → 致谢 → 附录。

**摘要写作要求**：300–500 字（本科）、800 字（硕士），须含研究对象、方法、主要结果
3–4 条（带关键数值）、结论。**最后一句必须写明研究的范围与局限**——这是评阅人最容易
抓的点，主动写比被问出来好。

---

## 三、图表规范

- **编号**：按章编号（图 4-1、表 3-2），与章节号挂钩；编号必须连续，`final_check.py` 会查。
- **题注位置**：图题在图**下方**，表题在表**上方**。
- **正文引用**：每个图表都必须在正文被引用，且按编号顺序首次出现。
- **分辨率**：位图 ≥ 300 dpi；线条图与示意图优选用矢量（PDF/EPS）。
- **配色**：考虑黑白打印。本工具默认 Okabe-Ito 色盲友好方案，灰度打印也能区分。
- **中文字体**：图上中文若字体缺失会显示方块。`figure_kit.py` 会探测并告警；
  或用英文标注规避。
- **图内不要写图题**：图题写在 md 里（`**图 4-1 标题**`），由排版脚本统一处理字号位置。

---

## 四、公式规范

- 公式按章编号：（2-1）、（3-4）；编号右对齐，公式居中（`build_docx.py` 已实现）。
- 公式中的变量在首次出现处解释；符号表建议放在第 2 章末尾。
- **Word 里没有真正的公式对象**：python-docx 无法生成 OMML。本流水线的做法是把
  LaTeX 转成 Unicode 文本（`math2unicode.py`），好处是可读、可复制、可打印，
  且脚本能校验"无残留 LaTeX"。**代价**是多重分式、矩阵等复杂结构无法完美呈现。
  若学校要求真正的 Word 公式，需改用 pandoc 之类工具链，属已知限制。
- 转换前的 md 源用标准 LaTeX（`\frac{}{}`、`\bar{}`、`$...$`），便于人工校对。

## 五、参考文献（GB/T 7714—2015 顺序编码制）

- **编号规则**：按正文**首次引用顺序**编号。编号由 `build_refs.py` 从正文自动推导，
  **不要手工维护**——本项目真实事故：手工编号在多次增删文献后与文献表整体错位两格，
  纸质校对根本看不出来。`check_refs.py` 会比对"正文提到的作者"与"该号对应文献的作者"。
- **正文标注**：`[1]`、`[3,6]`、`[5-7]`，上标或同字号均可。
- **著录格式**：
  - 期刊：`作者. 题名[J]. 刊名, 年, 卷(期): 起止页. DOI: xxx.`
  - 专著：`作者. 书名[M]. 版本. 出版地: 出版者, 年: 页码.`
  - 学位论文：`作者. 题名[D]. 保存地: 保存单位, 年.`
  - 标准：`标准编号 标准名称[S]. 出版地: 出版者, 年.`
  - 作者超过 3 位时列前 3 位后加", 等"。
- **核验**：每条文献的 DOI 必须真实。用 `paper-pipeline/scripts/litsearch.py verify`
  逐条核验，查不到的不要引。**被撤稿的绝对不能引**（`litsearch.py retract`）。

## 六、AI 使用与学术规范

- **如实声明 AI 使用**：参与哪些环节（文献检索、代码、图表、文字组织）、哪些由作者负责。
  隐瞒使用是学术不端。
- **不为规避检测改文体**：可以为了表达清晰而润色，但不能"洗稿式"改写以躲避查重。
- **数据与结论必须可溯源**：每个数值能追到 `data/` 文件或 `code/` 计算。
- **不编造**：文献、DOI、学校要求、期刊分区——核实不到就写"未核实"。

---

## 七、答辩 PPT 与汇报

- 篇幅：本科 12–18 页、硕士 20–30 页，**每页一个要点**。
- 结构：背景与问题（2–3 页）→ 方法（3–5 页）→ 结果（6–8 页，图要大）→ 结论与展望（2–3 页）。
- **必留一页"研究局限"**：主动说明局限比被评委问出来好。
- 预答辩问答准备见 `18_Cover Letter/DEFENSE_QA.md` 的做法：把最软的三处弱点先写成问答。

## 八、交付前自检（跑 `final_check.py`）

```bash
python scripts/final_check.py --dir <项目目录> --write
```

全绿才交付。报告落在 `20_投稿前总检/CHECK_REPORT.md`，哈希表落在 `deliverables/HASHES.txt`。
