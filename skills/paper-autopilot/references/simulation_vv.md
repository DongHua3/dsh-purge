# 仿真论文的验证与可复现（第 12 步作业指导）

> 术语定义取自 NASA-HDBK-7009A 原文（已抓取留存，见 `_sources/`）。
> 本项目在第五轮踩过的坑写在第六节——那些是最容易犯、也最容易被审稿人抓住的。

---

## 一、先把四个词分清楚（这是仿真论文的生死线）

NASA-HDBK-7009A 的原文定义：

> **Verification（验证）**：确定模型与仿真在多大程度上**符合其概念模型、数学模型
> 或其他构造中详细说明的需求与规格**的过程。
>
> **Validation（确认）**：在与模型/仿真用途相关的意义上，确定模型或仿真在多大程度上
> **准确表征了真实世界**的过程，并且要使用**事先定义并认可的"何种程度算吻合"的标准**。
>
> **Domain of Validation（确认域）**：所有使模型响应与参照数据吻合的输入参数集合所
> 构成的区域。
>
> **Data Pedigree（数据谱系）**：从数据源头经过其传输、存储、处理的各个方面，
> 到用于模型开发的最终形式的**可追溯记录**。

**中文语境里这两个词经常被混用，导致审稿人认为你没做验证。** 记住：

| | 比什么 | 回答的问题 |
|---|---|---|
| **Verification（验证）** | 数值解 **vs 数学解** | "方程解对了吗？" |
| **Validation（确认）** | 数值解 **vs 实验/实测** | "物理建对了吗？" |

**没有实验的纯计算论文，做不了 validation，只能做 verification。**
这不丢人，但**必须在文里写清楚**：你做了的是哪一类。
把 verification 写成 validation 是审稿人最反感的over-claim之一。

## 二、Code Verification（代码验证）：解收敛阶

方法：**制造解方法（Method of Manufactured Solutions, MMS）**。

1. 选一个已知的解析解（制造解），代进控制方程，反推出对应的源项/边界条件
2. 用这个源项和边界条件跑代码
3. 加密网格，看误差随网格尺度 h 的下降速率

误差与网格的关系应为 `E = C·h^p`，取对数：

```
p_observed = log(E2/E1) / log(h2/h1)
```

- **观测阶 p 必须接近代码的理论阶**（一阶格式 → 1，二阶 → 2）。
- 只有在**渐近区**（asymptotic range）里测才有意义——
  网格太粗误差没进渐近区，网格太细会被舍入误差淹没。
- **至少要三套网格**才谈得上"看趋势"。

**写作要点**：把三套网格的误差表、观测阶、理论阶列成一张小表。
这张表是"我的代码没问题"的最强证据，成本极低。

### 与你已有的解析解比对

很多工程问题有闭式解（悬臂梁挠度、简支梁频率、Euler-Bernoulli 理论值……）。
拿有限元结果和它们比是最省事的验证，但**必须同口径比**：

- ✅ 静态载荷下的挠度 vs 静态闭式解
- ❌ **模态刚度 `mω²` vs 静刚度 `192EI/L³`** —— 这两个不是同一个量
- ✅ 共振频率 vs 固有频率之前，先确认边界条件一致
- ✅ 有限元**体载荷**下的挠度 vs 均布载荷梁理论

**先声明容差，再比对。** 先比完再挑一个能过的容差，是学术不端。

## 三、Solution Verification（解验证）：网格无关性

**网格收敛指数（Grid Convergence Index, GCI）**，Roache 提出，是这一领域的事实标准：

1. 用**至少三套系统加密**的网格算出关注量 f（细 f₁、中 f₂、粗 f₃）
2. 网格加密比 `r = h₂/h₁`（结构网格常取 1.26 或 1.5，即网格数按 2 倍或 3.4 倍增长）
3. 观测阶

   ```
   p = |ln|(f₃−f₂)/(f₂−f₁)| / ln(r)|
   ```

4. Richardson 外推值

   ```
   f_exact ≈ f₁ + (f₁−f₂)/(r^p − 1)
   ```

5. 细网格的 GCI

   ```
   GCI_fine = Fs · |(f₂−f₁)/f₁| / (r^p − 1)
   ```

   `Fs` 是安全因子：三套以上网格且观测阶单调时取 **1.25**，只有两套时取 **3.0**。

**写作要点**：给出 `p`、`f_exact`、`GCI_fine`，并说明 fs 取值理由。
报告形式示例：「网格从 48 万加密到 380 万单元，峰值振幅的观测收敛阶为 2.04，
Richardson 外推值 35.72 µm，细网格 GCI = 0.8%。」

**没有做网格无关性 = 直接退稿。** 这是仿真论文最常见的死因之一。

## 四、Validation（确认）：只有你有实验数据时才谈

### 4.1 核心要求

- **事先定义"什么算吻合"**——不能事后定
- 对比必须**同口径**：同一个量、同一个工况、同一个定义
- 要给出**确认域**：你的模型在哪个参数范围里被确认过。
  超出这个范围的预测**必须标注为外推**，不能当作被验证的结论

### 4.2 ASME V&V 20 的思路

ASME V&V 20-2009 处理的是"数值解 vs 实验数据"的比对，
核心是把**数值不确定度 U_num** 和**实验不确定度 U_exp** 合成，
再与两者的**差值 E** 比较：

- 若 `|E| ≤ U_val`（其中 `U_val = sqrt(U_num² + U_exp²)`），
  则在该不确定度水平上**无法拒绝**该模型
- 若 `|E| > U_val`，模型与实验**不一致**，需要解释

**关键点**：不是"曲线看起来接近就算通过"，而是要和**不确定度**比。
不确定度是论文里必须给的量。

### 4.3 没有实验怎么办（本项目的情况）

诚实写法：

- 明确写"本文是计算研究，模型未经实验确认"
- 把验证做到位：与解析解比、做网格无关性、做参数敏感性
- 把这一条写进**摘要**和**独立的范围声明**，不要藏在文末
- 在局限里写清楚：哪些结论依赖模型假设，哪些是外推

**不要**用"与文献趋势一致"冒充 validation。
"趋势一致"不是确认，是一个待检验的观察。

## 五、不确定度量化（UQ）

### 5.1 两类不确定度

| 类型 | 含义 | 处理方式 |
|---|---|---|
| **Aleatory（偶然）** | 本质随机、不可通过更多信息消除：制造公差、材料批次差异 | 概率分布 + 抽样（Monte Carlo） |
| **Epistemic（认知）** | 知识不足造成、可通过更多信息减少：模型形式、参数真值未知 | 区间分析、灵敏度分析 |

**论文里要分开说。** 把两者混成一个"总误差"是不专业的。

### 5.2 公差 vs 标准差——本项目踩过的坑，写在这里给你避坑

**声明的公差是"界限（bound）"，不是"标准差（σ）"。**

本项目第二轮做 Monte Carlo 时写了 `rng.normal(0, tol)`，
把公差当成了正态分布的标准差。后果是：**约三分之一的抽样落到了声明的公差带之外**——
也就是说，报告出来的散布比你实际能保证的范围还大，而且物理上说不通
（"±2 mm 的公差"意味着 2 mm 之内，不是"以 2 mm 为标准差")。

**正确做法**：公差是界限，就在界限内按**均匀分布**抽样：

```python
import numpy as np
rng = np.random.default_rng(0)
# 公差 ±tol，均匀落在带内
draws = rng.uniform(-tol, tol, size=(n, ))
```

**这个错误很常见，而且审稿人会算。** 报告抽样结果时写清：
「公差按**有界均匀分布**抽样，n = 400 次，随机种子 0」。

### 5.3 抽样规模与报告

- 报告**均值 ± 标准差**、**5–95 百分位**、**最小值**
- 报告**落在阈值之外的样本比例**，用 **Wilson 区间**给它的置信区间
- 报告**参数灵敏度**（如 Spearman 秩相关），说明哪个输入主导了散布
- 给出**随机种子**和抽样次数，别人才能复算

只给一个"最坏情况"数是不够的；只给均值也是不够的。
**分布的形状本身是结论的一部分。**

### 5.4 极限情况要单独算

参数敏感性分析、公差传播、极限工况——这些往往给出比主结果更重要的结论。
本项目的一个例子：最坏 MRE 应变出现在**去磁状态**（5.74%），
而不是在受控状态，并且超出了 5% 的许用限值。
这个结论比"控制效果好"更有价值，作者应当在摘要里说，而不是藏起来。

## 六、一定要写出来、但常常被漏掉的东西

| 项 | 为什么重要 |
|---|---|
| **全部参数取值 + 来源**（自测 / 文献 / 假设） | 别人照着重做的前提；没来源的参数要显式标为假设 |
| **求解器名称、版本、求解设置**（单元类型、时间步、收敛判据、容差） | 复现的关键；"用 ANSYS 算的"不够 |
| **网格规模**（节点数/单元数）与网格无关性结果 | 见第三节 |
| **边界条件与理想化假设** | 假设没标，审稿人会以为你没意识到；标了就是方法学边界 |
| **硬件的坐标/单位制** | 单位混乱是低级但常见的错误 |
| **数据处理链**：从原始输出到论文数字的每一步 | 差一个中间步骤，数字就对不上 |

## 七、可复现性与数据/代码可得性

Nature Portfolio 的要求（其他刊趋势相同，见 `submission_and_compliance.md`）：

- **数据可得性声明是强制的**
- 优先存公共仓储：**Zenodo、Figshare、Dryad**
- **代码可得性声明**是独立一节，位于数据可得性之后、参考文献之前
- 代码存到能发 DOI 的仓储（**Zenodo、Code Ocean**），
  并**作为正式条目列进参考文献**
- 建议采用 OSI 认可的开源许可证
- 若代码对结论至关重要，**评审期就要提供给编辑和审稿人**

### 本项目的做法（可以照抄）

1. `code/` 下的分析脚本 + `ansys/` 下的求解器输入卡 + 派生数据 CSV/JSON +
   出图脚本，一起打包
2. 传 Zenodo，拿 **concept DOI**（版本更新时引用同一个 concept DOI）
3. 数据可得性声明里写这个 DOI
4. 代码可得性声明里写这个 DOI + 许可证
5. 参考文献里正式引用这个数据集（DataCite 格式：作者、标题、仓储名、DOI）
6. 附一份 `README`，说明**按什么顺序跑哪几个脚本**能复现全部数字

**没有真实实验的仿真论文，可复现性是唯一能拿的硬分。** 别人复算不出来，
你这篇论文的价值就是零。

## 八、审稿人怎么挑仿真论文的毛病（提前堵住）

| 常见意见 | 你要有的东西 |
|---|---|
| "没有验证" | 与解析解对比表 + 网格无关性 |
| "网格无关性没做" | GCI 表 + 观测阶 |
| "参数来源不明" | 参数表带来源列 |
| "假设没说明" | 独立的假设清单 |
| "和实验不符"（有实验时） | 不确定度合成 + 确认域 |
| "结论超出数据支持范围" | 确认域 + 外推标注 + 局限节 |
| "结果无法复现" | Zenodo DOI + README + 随机种子 |
| "只挑好的工况展示" | 全工况扫描图 + 最坏情况说明 |
| "模型太简化" | 说明简化对结论的影响，或做敏感性分析量化它 |

**最后一条往往最致命**：如果模型简化会影响结论，那就做一次敏感性分析把它量化。
量化之后它就从"缺陷"变成了"方法学边界"，性质完全不同。
