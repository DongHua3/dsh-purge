# 仿真、计算机模拟与数据溯源（第 10、12 步作业指导）

> **本文件配套脚本**：`scripts/simulate.py`　**配套模型目录**：`models/`
>
> 核心规则一句话：
> **`data/` 里的每一个数字都必须由真实运行的程序产生，并带有可核查的溯源记录。
> 手写、估算、或"看起来合理"的数字，一律不许出现在论文里。**

---

## 一、为什么这一步和文献核验同样重要

前面把"参考文献必须真实"解决了。但如果数据是编的，
那么**引用可查、数字不可查**——审稿人一看数据就不对，或者更糟：
发表后被复现失败，撤稿。

`synthesize` 之前，自检只能查到"正文里的数字在 `data/` 里有没有"。
它查不出 `data/` 本身是不是手写的。这一轮补的就是这个洞。

---

## 二、三段式：写模型 → 自检 → 跑数据

```
1. 写模型            models/<your_model>.py
                     （声明 PARAMS / verify() / STUDIES）
        ↓
2. 模型自检          python scripts/simulate.py check --model <name>
                     （对解析解、收敛阶、可复现性；不过就不许产数据）
        ↓
3. 跑数据            python scripts/simulate.py run --model <name> --study <s> --out data/x.csv
                     （自动写 x.csv 和 x.csv.prov.json）
        ↓
4. 溯源核查          python scripts/simulate.py provenance --data data/
                     （改过的数据、旧模型跑的数据，全部查得出来）
```

---

## 三、模型怎么写

放在 `models/` 下，一个 `.py` 一个模型。必须提供四个东西：

```python
NAME     = "my_model"          # 模型名
VERSION  = "1.0.0"             # 版本；改了模型必须升版本
PARAMS   = { ... }             # 全部输入参数，声明式写在这里

def verify(verbose=True) -> dict:
    """对解析解做独立验证，返回 {passed, checks:[...]}"""

STUDIES = {"sweep": study_sweep, ...}
# 每个 study(ctx) -> {"table": 名, "rows": [dict...], "columns": [...]}
```

**`PARAMS` 里不许有"从结果反推"的参数。** 每个参数要么是设计选择，
要么来自文献（标出处），要么是假设（标为假设）。这一条是仿真论文的底线。

### `verify()` 必须真的独立

**不能拿自己的输出验证自己。** 合格的验证是对**不依赖本代码**的东西比：

| 检查类型 | 比什么 | 检验了哪部分 |
|---|---|---|
| **解析解对照** | 闭式解（周期、稳态幅值、固有频率） | 积分器、矩阵装配 |
| **两种方法互校** | 时域积分 vs 频域解 | 求解路径是否一致 |
| **收敛阶** | 观测阶 vs 理论阶 | 离散化是否正确实现 |
| **可复现性** | 同输入跑两次是否逐位一致 | 有没有隐藏的随机源 |

### 本技能自带的 `rotor_mre_dva` 模型（真实可用）

两自由度转子 + 磁流变弹性体动力吸振器，六项自检实测结果：

```
A. 自由振动 周期（RK4 vs 2*pi*sqrt(m/k)）        相对误差 4.4e-16  PASS
B. 简谐受迫 稳态幅值（时域 vs 解析）              相对误差 9.0e-09  PASS
C. 2-DOF 一阶固有频率（特征值 vs 解析根）          相对误差 2.2e-16  PASS
C. 2-DOF 二阶固有频率（特征值 vs 解析根）          相对误差 0.0e+00  PASS
D. 2-DOF 峰值 |x1|（时域积分 vs 频域解）          相对误差 1.3e-08  PASS
E. 时间步收敛 观测阶（RK4 理论阶 4）              实测 3.949       PASS
F. 相同输入重复运行 完全一致                      逐位相同          PASS

7/7 通过
```

**可以直接用它，也可以照它的样子写你自己的模型。**

## 四、数据溯源：怎么防止数据被改

每次 `run` 都会写一个 `<文件>.prov.json`，记录：

| 字段 | 作用 |
|---|---|
| `file_sha256` | 数据文件的指纹——**改一个数字就对不上** |
| `model_source` + `model_sha256` | 生成它的模型源码及指纹——**模型改了，旧数据立刻失效** |
| `parameters` | **完整**参数集 |
| `seed` | 随机种子（Monte Carlo 必须给） |
| `study` / `rows` / `columns` | 跑了什么、多少行 |
| `verification` | 生成时模型自检过没过 |
| `environment` | Python / numpy 版本、平台 |

`simulate.py provenance` 会逐条核对。实测三种情况：

```
=== 正常 ===
  [ok    ] speed_sweep.csv  (rotor_mre_dva.speed_sweep, 1446 行, 2026-09-20T23:30:54Z)
  可溯源 2 · 有问题 0

=== 改了一个数字 ===
  [有问题] material_law.csv —— 数据文件在生成之后被改动过（指纹不符）

=== 模型改了但数据没重跑 ===
  [有问题] speed_sweep.csv —— 模型源码已改动，这份数据是用旧版本跑的，需要重跑
```

### 为什么"模型改了旧数据失效"这条很重要

论文改到一半你调了个参数、修了个公式——**之前跑的数据全部作废**。
没有这条机制，很容易拿旧数据配新公式，最后数字对不上，
而且自己都不知道是哪里错的。

## 五、`selfcheck.py` 如何强制

`selfcheck.py` 会：

- 发现 `data/` 里有文件但**溯源核查不过** → **阻断**
- 发现 `data/` 是空的（而这是计算研究）→ **警告**（提醒你数据还没跑）

第 12 步的必需产出也加了 `data/` 和 `12_方法与结果/model_verify.json`
——**没跑过仿真就交不了第 12 步**。

## 六、Monte Carlo、公差与不确定度（最容易出错的地方）

### 6.1 声明的公差是**界限**，不是标准差

这是本项目踩过的真坑：第二版把公差当 σ 用（`rng.normal(0, tol)`），
结果是**约三分之一的抽样落到声明的公差带之外**——
报告出来的散布比你承诺的范围还大，物理上说不通。

**正确做法**：公差是界限，就在界限内按**均匀分布**抽：

```python
draws = rng.uniform(base * (1 - rel), base * (1 + rel))
```

`models/rotor_mre_dva.py` 的 `study_monte_carlo` 就是这么写的。

### 6.2 报告什么

- **抽样次数 n** 和**随机种子**（别人才能复算）
- 均值 ± 标准差、5–95 百分位、最小值
- **落在阈值之外的样本比例**，并用 Wilson 区间给它的置信区间
- **参数灵敏度**（如 Spearman 秩相关），说明哪个输入主导了散布

只给"最坏情况"不够，只给均值也不够。**分布的形状本身是结论的一部分。**

### 6.3 最坏情况往往在反直觉的地方

本项目的一个例子：最坏 MRE 应变出现在**去磁状态**（5.74%），
不是在受控状态，而且超出了许用限值。
**这个结论比"控制效果好"更有价值**，应写进摘要而不是藏起来。

## 七、网格/时间步无关性

论文里必须有。做法：

1. 用**至少三套**系统加密的网格（或时间步）
2. 算观测收敛阶 `p = log(E₂/E₁) / log(h₂/h₁)`
3. 与格式的**理论阶**比
4. 报 GCI（网格收敛指数）：`GCI = Fs·|(f₂−f₁)/f₁| / (r^p − 1)`，
   安全因子 `Fs` 三套以上取 1.25

**两个实测教训（都写进了 `rotor_mre_dva.verify()`）**：

1. **网格必须粗到误差还在渐近区。** 本模型第一版用 1000/2000/4000 步每周期，
   RK4 的误差已经到机器精度了，测出来的"收敛阶"是 8.39——纯噪声。
   改成 40/80/160 步后得到 **3.949**，与理论阶 4 相符。

2. **测的量必须是积分量，不能是采样峰值。**
   采样峰值的误差取决于"采样点是否落在波峰上"，那是**一阶**收敛，
   跟积分器的四阶无关。本模型第一版用 `max(|x|)` 测，order 报 8.32；
   改成**最小二乘拟合正弦幅值**后，order = 3.949。

   > 这两条是通用的：**任何"看起来不对的收敛阶"，先怀疑测量方法，再怀疑代码。**

## 八、验证与确认的区别（别把话说满）

| | 比什么 | 回答 |
|---|---|---|
| **Verification 验证** | 数值解 vs **数学解** | "方程解对了吗？" |
| **Validation 确认** | 数值解 vs **实验** | "物理建对了吗？" |

**纯仿真论文做不了 validation，只能做 verification。**
这不丢人，但必须在文里写清楚，并把这一条写进**摘要**和**范围声明**。
把 verification 写成 validation 是审稿人最反感的 over-claim 之一。

详见 `references/simulation_vv.md`。

## 九、给 agent 的执行纪律

1. **禁止手写 `data/` 里的数字。** 必须用 `simulate.py run` 跑出来。
2. **模型改了必须重跑数据。** `provenance` 会拦，别绕过。
3. **模型自检不过就不许产数据。** `run` 默认会拒绝；
   `--skip-verify` 只能用于排查问题，产生的数据不能进论文。
4. **`PARAMS` 不许有反推参数。** 每个参数标清是设计值、文献值还是假设。
5. **Monte Carlo 必须给种子**，公差按均匀分布抽。
6. **收敛性检查要用粗网格和积分量**，否则测出来的是噪声。
7. **数据文件不要手工编辑**——要改就改模型重跑。
8. **没有实验就必须写明**，不能把 verification 说成 validation。

## 十、环境依赖

| 需要 | 说明 |
|---|---|
| `numpy` | 模型与数值计算 |
| 无网络要求 | 仿真完全本地运行 |

`simulate.py` 不需要任何外部求解器。若用 ANSYS/COMSOL 等商业软件，
把它们的输入卡与输出文件一起放进 `data/`，并在 `provenance` 里手工登记
（参照 `.prov.json` 的字段），**同样要记录软件版本与求解设置**。
